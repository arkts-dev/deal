# C11 runtime

The published native runtime. `deal/native/deal_rt.h` is the one ABI declaration authority: it carries the canonical host-abi record set unchanged (field order, enum discriminants, signatures, registry externs and the count-zero sentinel), the error-first outcome family, the `deal_origin` transport record and the opaque runtime representations, and it reaches every service group header in dependency order. Generated code includes only this header; it never includes an internal structure. `deal_module` and `deal_export_entry` are incomplete types in every runtime translation unit — their layout exists only in the emitted project module, so no header, group or helper may define, allocate, size, fill or read them. Each service group is one translation unit plus its header, every operating-system call lives in `platform.c` alone and the overflow-checked size arithmetic of every size that reaches the platform allocator (`deal_platform_checked_add`/`_multiply`/`_round`) lives there beside it, so an allocation's header-and-payload total, its alignment, a page round and a completion payload's growth are the one deterministic resource fault when they cannot exist instead of a wrapped short region, and every published unit must compile under `-std=c11 -Wall -Werror -Wextra -pedantic` at `-O0` and `-O2`. Compose failure text never in C: the runtime materializes failures from the emitted closed arm table, which the module installs through `deal_arm_table_install` before any user code, and a structurally invalid table is one deterministic stderr line and exit 2. Errors keep one identity and one immutable origin, snapshots are innermost-first, and absent error fields are reported absent, never as empty strings. Resource and invariant faults reuse `deal_platform_fault` — the only spelling — and are never language-visible `Error`s. Completion frames are platform memory with copied bytes: no managed pointer and no error token, exclusive producer ownership before publication, exactly-once consumer release, one consumer, and release/acquire publication. A managed object's payload is preceded by a runtime-private header; no published header declares an object header, an offset or a size of one, and `deal_data`/`deal_layout` are the only structural value records (their `reference` and `reference_offsets` members carry the precise map the collector walks). Rooting is precise: every root source enumerates managed referents only, so a nullish singleton, a scalar payload and a crossing handle are never traced as heap addresses. A layout whose payload holds managed references outside its fixed reference map registers its own resumable walk with `deal_layout_trace_register` at its first use (the `container` group walks an array's element storage that way: each call visits at most the caller's reference budget and answers the position to resume at, so one wide array is traced across several safepoints), so the collector never derives another group's layout or element stride and no slice is unbounded by object count. A layout whose payload owns platform storage beside the managed heap registers one reclamation hook with `deal_layout_release_register` at its first use (the `error` group releases a reclaimed Error's copied code, message and origin text, its optional expected/actual text and its frames array with one duplicated label per frame that way), and the sweep runs the hook while the payload is still intact, so reclaiming a record strands no platform storage. Exactly one collection configuration exists: allocation always runs the safepoint, the growth policy starts and advances cycles without an explicit call, and the collected runtime has no staged or selectable non-collecting mode. Later children extend these files and this header set; they never redefine a delivered entry. The `text` group also owns the one concatenation entry the emitted templates call, and the `error` group the builtin Error's own class fields as DEAL strings: a class-literal `Error` construction copies its supplied `code` and `message` into the record's platform text, and a field read or write of those two fields goes through the group's own entries, so the instance a program constructs, throws, catches and mutates is the same object with the same origin, frames and cause.
