# C11 runtime

The published native runtime. `deal/native/deal_rt.h` is the one ABI declaration authority: it carries the canonical host-abi record set unchanged (field order, enum discriminants, signatures, registry externs and the count-zero sentinel), the error-first outcome family, the `deal_origin` transport record and the opaque runtime representations, and it reaches every service group header in dependency order. Generated code includes only this header; it never includes an internal structure. `deal_module` and `deal_export_entry` are incomplete types in every runtime translation unit — their layout exists only in the emitted project module, so no header, group or helper may define, allocate, size, fill or read them. Each service group is one translation unit plus its header, every operating-system call lives in `platform.c` alone, and every published unit must compile under `-std=c11 -Wall -Werror -Wextra -pedantic` at `-O0` and `-O2`. Compose failure text never in C: the runtime materializes failures from the emitted closed arm table, which the module installs through `deal_arm_table_install` before any user code, and a structurally invalid table is one deterministic stderr line and exit 2. Errors keep one identity and one immutable origin, snapshots are innermost-first, and absent error fields are reported absent, never as empty strings. Resource and invariant faults reuse `deal_platform_fault` — the only spelling — and are never language-visible `Error`s. Completion frames are platform memory with copied bytes: no managed pointer and no error token, exclusive producer ownership before publication, exactly-once consumer release, one consumer, and release/acquire publication. Every entry-surface symbol has exactly one definition per build shape: the module owns the six export-surface functions and its arm table, `entry.c` owns the terminal, `error.c` owns the accessors and the call-frame stack, `memory.c` owns the root frames and accepts the zero-slot frame the emitted skeleton pushes (a frame with no slots touches no slot storage and forms no pointer from the possibly unallocated slot table), and `main.c` owns the product build's process entry. Later children extend these files and this header set; they never redefine a delivered entry.
