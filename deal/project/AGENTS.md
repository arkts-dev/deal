# Project Configuration

Own strict manifest parsing, project discovery, roots, outputs, and external declarations. Validate before overrides or output creation. Normalize paths once while preserving configured identity where required. A manifest is optional: absent configuration uses the resolved entry directory as base/root and current-language defaults without creating a file or inventing manifest ranges. Present manifests remain strictly validated. Require the specification's languageVersion and matching stdlib (the default when absent); reject other manifest versions before publication. Keep one backend name authority across the CLI alias set, the manifest validator, the default-output table and the compile pipeline, so the accepted names and their rejection texts never disagree. Source/declaration directives cannot select a version. Stdlib discovery publishes only console/string/table/math/time declarations; a stray JSON declaration does not acquire stdlib identity. Preserve canonical alias and regular-file filtering controls on supported modules. Configuration failures remain deterministic and publish nothing. Optional batch schema validation shares default rules/order, suppresses dependent checks for invalid containers and never returns a partial manifest; strict-walk faults remain fail-fast.
