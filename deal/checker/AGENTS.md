# Checker

Own resolution, typing, narrowing, and explicit checked facts. Diagnostics and fact production must be deterministic and target-neutral. Expose every fact semantic lowering needs; emitters must not rediscover source meaning. An import alias carries its module's own declared class symbols, so a qualified annotation's construction context, field access, delete target and has check read the alias's exact declaration, never a same-spelled local declaration, a textual class-name search or an identity-first alias. A class-typed receiver the annotations did not attribute (a call result, an awaited value) still resolves the declaration its own bound carrier's defining provider names. Every class-typed annotation pins its exact declared class symbol (bare local name, qualified alias declaration, or the inner class leaf of a nullable/array wrapper). The canonical class identity names the defining file, so two same-named sibling files are distinct nominal types and a direct assignment across them is the named cross-declaration rejection (E3019) at every assignment boundary — declaration initialization, assignment, call argument, declared return, array element or class-literal field. A class type additionally carries its declaring module's wiring key as its defining provider: two bound providers of two same-named declarations never retag a value (the same E3019), and same-provider values stay compatible. Every class-typed expression publishes its exact declaring declaration through the checked result: an annotated binding, field or array element through its own annotation, and a call result, awaited value or other inferred expression through its own bound carrier's defining provider — never a same-identity name scan, so a receiver's field, delete and has decisions stay independent of the discovery order. A constructed literal publishes its exact declaration from its construction context — the enclosing annotation, the enclosing class field's own declared annotation (a class-typed field's value is laid out by that field's declaration, so a nested literal of a same-spelled sibling provider is never captured by the enclosing literal's contextual declaration), the callee parameter (resolved through the imported module's own declared function symbol and the parameter's own annotation in the callee's declaring module, or a function-typed callee's own bound parameter carrier), or the current function's declared return annotation — or from its own bound carrier when no context named one; a contextual declaration whose defining provider differs from the carrier's bound provider never captures the literal, and a same-named sibling provider never captures the construction; the one lowering refuses a multiple-declaration identity only when no exact declaration resolves (a carrier-shared identity a valid project never produces, because the identity names the defining file). The one lowering selects the exact declaring provider of a field operation and attributes a literal's resources to its own construction declaration instead of re-resolving a name or an ambiguous canonical identity. Test accepted and rejected forms. Every class field annotation resolves and reports unknown types even when the class is not jsonable and no literal constructs it. Class literal checking validates every provided value against its field's exact declaration and requires every non-optional field, including nullable fields and builtin Error's code/message. Publish the null-narrowing refinement as a checked fact: every identifier read whose declared type is `T | null` and whose checked type is `T` is recorded in `CheckResult.narrowedReads`, so the one lowering validates that read at the operator operand, condition, index receiver/key, table member receiver, `.length` receiver, for-of iterable and `has` receiver positions (the positions no typed boundary owns) and never re-derives the refinement from a lexical name — the narrowing analysis and its scope-correct binding resolution stay the checker's. A declared nullable read keeps its declared type (the null tests stay null tests), and the refinement never crosses a function boundary. An optional field read publishes the canonical `T | null` wrap (`Types.nullableOrSelf`): a required-present read keeps the declared type, and a field declared `null` reads as `null` (`null | null` is `null`), so the checked read type and its descriptor agree with the spec's optional-read rule without ever naming a `Nullable<Null>` form. Calls resolve ordinary visible bindings in declaration order; no numeric conversion seeds exist. An unresolved `bytes` type or value is an ordinary unknown-name error; user declarations with that identifier resolve normally. A catch identifier declares a local `Error` variable, so it carries the same user-declaration `$` prohibition as every other binding; its E2008 anchors on the catch identifier's own span, never the whole try statement. Table literal property names and table member reads are dynamic string keys, not declarations, so `$` in that key data stays admissible while a class field read stays the declared-field decision.
