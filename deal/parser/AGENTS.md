# Parser

Parse specification grammar, decoding validated multiline untagged-template text once while retaining raw source ranges. Preserve exact UTF-16 source ranges and deterministic recovery. Comments supply no metadata or compiler directives, including inside nested template interpolations; retain their line terminators for grammar restrictions. Declaration identifiers, including catch bindings, retain token spans alongside containing-node spans for checker diagnostics. Expression statements beginning with function/async function require parentheses; class fields cannot be named constructor. Accept other keyword properties; async/as/from/of also admit contextual bindings/references. Nonempty call, declaration/expression parameter and function-type parameter lists admit one trailing comma; empty comma-only lists and omitted elements remain invalid. Typed sync/async arrows require parenthesized annotated parameters and an explicit result annotation; block and expression bodies share ordinary function-body lowering. Enforce no line terminators before => or after async, including comment-contained terminators. Conditional expressions bind below logical operators and above assignment; parse both arms as assignments with right association. Arrow lookahead distinguishes an annotated parameter head from a parenthesized consequent followed by a conditional colon. Keep checker and backend policy outside parsing. Add focused accepted and rejected fixtures for grammar changes. Project manifests alone own language versions; source has no version directive or version AST metadata. Class fields carry type, presence and nullability only. Reject an initializer at its `=` token with E1007; recover without retaining an initializer AST. Keep policy synchronized.
