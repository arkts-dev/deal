# LuaJIT Backend

Emit LuaJIT artifacts from validated semantic IR while preserving Lua ABI, typed host loading, async, errors, and evaluation order. Extend LuaSemanticEmitter for semantics; never restore AST emission. Verify Oracle parity and real luajit execution. Declared host classes construct fresh tagged instances from provided, boundary-validated fields, never a copied defaults map. Loading and construction never read `<C>_defaults`; required omissions reject, including both builtin Error fields, and omitted optionals stay absent. Array-slot trace indexes use canonical binary64 hexadecimal spelling, including signed zero, rather than Lua's decimal formatting. The emitted comparison helper selects the nullable-null row's named operand (`side`) with an explicit branch, never Lua's `and`/`or` idiom, so a false-valued operand stays the compared value while both `NULLABLE_NULL_EQ` and `NULLABLE_NULL_NE` keep only null and the internal missing sentinel as the null-equivalent pair. Carrier identity, container length, insertion order and the per-slot numeric-variant marks are keyed by the process-wide private table keys (`__dealCarrierKeys`, adopted by `deal/runtime.lua`), never by string fields: a DEAL table may carry any string key (a class field or a JSON member may be named after any of them) and a table value never forges a class, Error, function, array, async or numeric-variant carrier. Classification reads those keys only; the documented host-module authoring shapes (`__rt.function_`, `__rt.export_class`, the `{__kind, sig, f}` / `{__kind, __classname}` host exports) stay accepted at the host-load boundary and normalize into the private-marked representation. The host-crossing projection hands the raw host the declared DEAL value: the sync parameter cell, the async-argument crossing and the class-field projection unwrap a numeric-variant carrier to its number at every declared position (array elements and object members recursively, class fields in place) while the container identity, alias behavior and the per-slot numeric-variant marks are preserved, so an echoed decoded container re-encodes its own `int`/`number` spellings — the JVM boxed-carrier unwrap and the JS `$hostProjectValue` leaves. An inbound plain Lua table the raw host returned or passed at a declared `table` position is the table value: `TABLE_KEYS` takes its present string keys and `JSON_STRINGIFY` encodes its JSON-shaped content (the dense 1..n numeric form as an array, other tables as objects over their string/numeric key texts, with the recorded per-slot marks), so no raw `#nil` failure or false `E8001` arises; a table that already carries a produced carrier mark keeps its recorded order, marks and DEAL identity. An inbound plain Lua table at a declared array position is the DEAL array value only when it has the value mapping's 1-based contiguous storage (every key a positive integer, every one-based slot present, where a nullable element position's absent slot is the matcher's null admission): every host-to-DEAL crossing — the async-function completion value and the parameter entry of a DEAL callback the host invokes — runs the pair's inbound projection at the position's declared descriptor (nested arrays, null elements, class identities and aliases preserved, one memo per crossing), so the body reads `.length`, the elements at every one-based slot and a declared class instance's top-level declared fields, while a map table, a sparse table at a non-nullable element position or any other non-array table is left unprojected so the position's typed-boundary cell raises the closed kind failure instead of an emptied or truncated array. Every declared callback parameter position then runs its recorded parameter-entry cell with the projected value or nil for an omitted argument, so a non-nullable omission fails closed and a nullable omission takes the null mapping, and a raw Lua function at a declared function position takes the closed kind row (never an internal index of the function value). A raw nil array slot is the internal missing/deleted element and never serializes as JSON null, in the emitted walk and the shipped `std/json` alike; a present object member the presence map records stays a JSON null member (the chunk's JSON_PARSE graph stores no value for it), and the shipped `std/json` parse records the same per-slot `int`/`number` variant marks the emitted prelude writes. One pair of factory-store helpers (`__factories.__hostCarrierOut`/`__hostCarrierIn`, ISSUE-0850) is the single representation-directed projection every host crossing delegates to — the host async completion crossing (ISSUE-0853) runs `__hostCarrierIn` with the completion descriptor and one memo per await after the numeric-variant materialization and before the single `ASYNC_COMPLETION` cell, so a declared host-class completion is the dual-tagged DEAL instance (nested class fields, array fields with their exact elements/length/marks, absent optionals and present nulls, aliases, the host object unmutated), a class-element array completion keeps its elements, length and alias identity, a table completion keeps its identity where no member needs re-representation and otherwise takes one memoized copy with its class members bridged and its function members kept as wrappers, a numeric completion keeps its materialized variant, a function completion keeps the wrapper, and the crossing's START atom still atomizes the raw completion while the completion cell stays the sole failure authority: descriptor-directed at declared positions and value-directed at untyped positions, total, idempotent, and memoized per crossing; a chunk class carrier becomes a runtime instance with top-level declared fields and the carried identity, a dual-tagged host-class instance keeps its identity until a declared field needs re-representation and then becomes a fresh tagged copy, and a host-origin instance crosses by identity with only the landed numeric projection; inbound, a host-class instance becomes a fresh dual-tagged instance while a DEAL identity keeps the private `__f`/`__p` carrier; the builtin `Error` carrier and its runtime instance shape map both ways; containers keep their shared identity and in-place numeric marks until a class/function/Error element or member needs re-representation and then become one memoized copy with the carrier marks, an inbound `__a`/`__t` carrier carrying a host representation (the host echoed a DEAL value the outbound direction re-represented) takes the same value-directed walk over its elements/members with its length, presence/order maps and per-slot numeric marks preserved and its aliases memoized while one already holding DEAL values keeps its identity, a dense host table is an `__a` carrier only at a declared array position, and a sparse/map table is left for the declared cell; a DEAL function carrier becomes the documented `{__kind = "function", sig, f}` wrapper through the one `__hostFnArg` adapter (ISSUE-0854) with the emitted `__hostFnShapes` cells, and that wrapper runs the inbound projection at each recorded cell's canonical descriptor with one memo per invocation, then the declared parameter-entry cell, then projects the declared return value at the same entry's `ret` before the host observes it, so a declared function position, an untyped table member and a host class's function-typed field all cross through that one adapter while a wrapper and a raw Lua function cross unchanged; the walk is descriptor-directed, so a declared scalar position crosses unchanged in both directions (the declared cell remains the sole failure authority) and a later deep or cyclic subtree at a scalar element position is never inspected while an untyped or class/table/array position takes the full walk; the pair composes no DEAL failure (a missing shape entry is a plain producer diagnostic), never mutates the DEAL-side value beyond the landed in-place numeric projection (a class value's own fields, nested class values included, take that same walk), and never mutates a host-origin object beyond that same in-place numeric projection.
