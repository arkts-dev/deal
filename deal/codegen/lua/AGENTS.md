# LuaJIT Backend

Emit LuaJIT artifacts from validated semantic IR while preserving Lua ABI, FFI, async, errors, and evaluation order. Extend LuaSemanticEmitter for semantics; never restore AST emission. Verify Oracle parity and real luajit execution. Carrier identity, container length, insertion order and the per-slot numeric-variant marks are keyed by the process-wide private table keys (`__dealCarrierKeys`, adopted by `deal/runtime.lua`), never by string fields: a DEAL table may carry any string key (a class field or a JSON member may be named after any of them) and a table value never forges a class, Error, bytes, function, array, async or numeric-variant carrier. Classification reads those keys only; the documented host-module authoring shapes (`__rt.function_`, `__rt.export_class`, the `{__kind, sig, f}` / `{__kind, __classname}` host exports) stay accepted at the host-load boundary and normalize into the private-marked representation. The host-crossing projection hands the raw host the declared DEAL value: the sync parameter cell, the async-argument crossing and the class-field projection unwrap a numeric-variant carrier to its number at every declared position (array elements and object members recursively, class fields in place) while the container identity, alias behavior and the per-slot numeric-variant marks are preserved, so an echoed decoded container re-encodes its own `int`/`number` spellings — the JVM boxed-carrier unwrap and the JS `$hostProjectValue` leaves. An inbound plain Lua table the raw host returned or passed at a declared `table` position is the table value: `TABLE_KEYS` takes its present string keys and `JSON_STRINGIFY` encodes its JSON-shaped content (the dense 1..n numeric form as an array, other tables as objects over their string/numeric key texts, with the recorded per-slot marks), so no raw `#nil` failure or false `E8001` arises; a table that already carries a produced carrier mark keeps its recorded order, marks and DEAL identity. An inbound plain Lua table at a declared array position is the DEAL array value: every host-to-DEAL crossing — the async-function completion value and the parameter entry of a DEAL callback the host invokes — runs the identity-preserving projection the synchronous host return runs (nested arrays, null elements and aliases preserved), so the body reads `.length` and the elements at every one-based slot, and each declared callback parameter then takes the DEAL parameter-entry cell, so a host-passed value outside its declared type never reaches the body. A raw nil array slot is the internal missing/deleted element and never serializes as JSON null, in the emitted walk and the shipped `std/json` alike; a present object member the presence map records stays a JSON null member (the chunk's JSON_PARSE graph stores no value for it), and the shipped `std/json` parse records the same per-slot `int`/`number` variant marks the emitted prelude writes. Keep this file always synchronized with code.
