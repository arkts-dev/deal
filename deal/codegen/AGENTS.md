# Code Generation

Translate validated semantic IR into target representation without redefining language semantics. A detached function missing its owning body-membership row rejects with the producing closure's exact origin, never a raw null dereference. Preserve boundaries, evaluation order, errors, and ABI behavior. The canonical class identity names the defining file, so two same-named sibling files are two identities and each emits its own layout, plan and carrier; for a carrier-shared identity (a harness-synthesized identity a valid project never produces) the emitted JSON plan table carries the unique plan-bearing (`@jsonable`) declaration's structural layout and exact nested links, and the generated carrier class carries the union of the identity's declarations' field names so either declaration's construction sites find their own slots; the JavaScript renderer instead keeps every declaration's layout and construction metadata per declaring unit and resolves cross-module `C$fields` reads through the plan-bearing declaration, so neither construction borrows a sibling's flattened field set. Every production backend renders semantic IR; the AST-consuming emitters are retired and no fallback route exists. `JsSemanticEmitter` is the JavaScript semantic-IR renderer (one CommonJS artifact per implementation unit, coordinate-only maps recorded through the shared `SourceMapRecorder` with local/foreign placement and one version-1 sidecar per artifact). `ProductionProjectEmission.run` selects it for `Backend.JS` as the one rendering invocation over the one lowered project, so the JavaScript production artifacts of a compile come from that single call; the public dispatch has one production arm for every backend: no AST emitter exists and no invocation purpose selects an alternate rendering (ISSUE-0805). The JavaScript renderer's `LOOP(FOR)` arm emits the body block's cell declarations, the body ops and the recorded update block inside one per-iteration scope, so the update block's carry transfer reads the very cell the finished iteration produced while a `let` cell stays a fresh live binding per iteration (a `continue` re-runs the recorded update block at its own transfer site, inside that same scope); the LuaJIT and JVM renderers need no such grouping because their cells are state slots rather than lexical locals. Class construction consumes provided values only, validates them in declaration order and publishes no instance on failure. Every nonoptional field must be provided, including nullable fields and both builtin Error fields. Host class metadata never requires, reads or executes a defaults hook; omitted optionals remain absent. JSON decoding follows the same presence contract and rejects missing required keys without invoking factories or evaluators. The recorded THROW keeps the thrown Error instance: a constructed Error's first throw materializes its own origin/frames on the identical value (the LuaJIT carrier's `o`/`f` fields, the JVM `JvmRuntime.raise` binding and the JS `$rt.throwValue` location write) and never allocates a replacement, an already-transported value is re-raised unchanged, and a handler's new failure keeps its own carrier as well — the JVM catch wrapper adopts the replacement's carried identity (`JvmRuntime.wrap`) and the LuaJIT wrapper commits the cause on the failing transport table, so the enclosing catch binds the instance the program threw. A captured catch binding is a shared cell whose catch entry publishes a fresh cell per catch execution (the LuaJIT cell table, the JVM Object[1] box, the JavaScript catch-clause let binding), so a closure created in an earlier catch keeps its own live cell and the next catch never rebinds it, while the catch binding's own BINDING_ALLOC never resets a live catch cell; the JVM try/catch arm names its caught-failure, replacement-failure, wrapped-failure and transfer locals by the op's own id, so a try/catch nested inside another handler's catch clause stays legal Java. Architectural direction never expands assigned task scope. Every production emission installs the project source-map recorder: source comments and per-source `.deal.map.json` sidecars are the v1.3 default, and the accepted `--source-map` spelling selects nothing. Keep this file always synchronized with code.
