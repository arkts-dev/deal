# Native LLVM Code Generation

Render the one validated lowered project as one deterministic textual LLVM module (`deal.codegen.llvm.LlvmSemanticEmitter`), and let `deal.module.ProductionProjectEmission` stage it plus the closed `NativeRuntime.FILES` set. Consume only `ExecutableLoweredProject` with its body tables, factory registries and declaration facts: never an AST, a checker object, or a native-only language rule. Keep the closed-set classifier authoritative: every operation kind, payload variant, selector, boundary kind, stdlib operation, failure arm, control selector, call mode, target kind and module-import kind carries exactly one decision in `LlvmStageClassifier`, and a fact outside the staged scalar skeleton raises one `SharedEmissionFailure` with that operation's own origin, which the production arm projects as the single E6005 `SHARED_EMITTER_COVERAGE`. Render only the external references the emitted facts need, each one published by `LlvmRuntimeAbi`: the call-frame and root-frame prologue/epilogue entries, the emitted arm table and its install entry, the one string comparison (`deal_text_compare`), the closed data relation (`deal_data_same`), the two nullish singleton predicates, the type-name projection and the descriptor-driven check. Every generated activation pushes its frame label, enters its root frame with the statically known slot count, and leaves and pops on every exit path; every managed-typed slot that can be live across an allocating call owns one root slot written at definition (a persistent datum through the tag-aware entry, a managed pointer directly, a reference-nullish operand only when it is no nullish singleton), and a scalar or code-pointer slot owns none. Keep `LlvmRuntimeAbi` the single Java mirror of the published headers, in the published declaration order, with `LlvmTypeMapper` the one C-to-IR and descriptor-to-representation mapping, the one pointer-type constructor and the one record-size rule that decides when a published record crosses the C ABI through a hidden `sret`/`byval` pointer; a new runtime entry extends the mirror in the same change. `LlvmSelectorArms` is the single rendering authority of the closed binary and unary selector families: one arm per merged member, with C6's pinned IEEE predicates, the one string-comparison authority, the distinct nullish singleton/tag tests, the closed data relation, managed identity, `fneg`, `xor i1`, the type-name projection and the nominal tag test, and no fast-math flag on any instruction; every runtime-entry arm carries that entry's own result encoding, so `deal_text_compare`'s `-1`/`0`/`1` ordering is compared against zero with the selector's predicate while `deal_data_same`'s `1`-when-equal truth is compared against zero with the inverted one. A `BRANCH` over the logical selectors enters the recorded right-operand block on true for `LOGICAL_AND` and on false for `LOGICAL_OR`, keeps the left operand's value as the skipped path's result, and every rendered call or import tests its carried Error explicitly so the continuation stays reachable. Every failure path returns the enclosing activation's own C4 outcome shape, derived from the lowered function that path belongs to: a `number`, `boolean`, scalar-nullish or `unknown` result keeps its value slot empty on failure instead of degrading to the error-only aggregate, and a returned outcome slot is narrowed back to the SSA spelling only for the two managed pointer shapes whose SSA type differs (`string` and `Error`), because a scalar-nullish aggregate, a `double`, a persistent datum and a code pointer are already their own slot type. A value whose C3 representation this stage does not construct is never admitted into a position that would need it: a function value is the managed `deal_fn*` closure carrier of C5, so `LlvmTypeMapper.admits`/`convertible` reject it at every `unknown` position (declaration, assignment, parameter, return, import/export) as the boundary's own origin-bearing E6005 instead of publishing a `deal_data` whose managed tag would hold a `.text` address — and the function-tagged datum the `typeof` projection builds carries only its tag, with a NULL `reference`, exactly as `deal/native/value.h` requires (the `reference` member is the managed payload for the managed tags and always NULL otherwise). Each binding's declared descriptor comes from the `VARIABLE_DECLARATION`/`VARIABLE_ASSIGNMENT` boundary the lowering emits between that write's value and its commit op, resolved per write and never from a bare value id: the lowering reuses a function-valued identifier's value id for its `BINDING_LOAD`, so a value-keyed lookup would give one binding another binding's declared type. A structure op whose recorded child paths all return or throw leaves its join without a predecessor: render that tail as `unreachable` and emit no fall-through epilogue, never an E6005 for a valid program. Emit the closed failure-arm table as data in the published `deal_arm_record`/`deal_arm_table` layout, in the registry's canonical order, and install it in `deal_project_start` before any unit's initialization. The module owns `deal_module`, `deal_export_entry`, the two scalar nullish representations and the six export-surface definitions, defines no process entry and no runtime-owned symbol, and carries the pinned triple, both debug names per function and project-relative file names. Derive every name, order and record from IR facts: no map iteration order, timestamp, absolute path or environment text reaches the bytes.
