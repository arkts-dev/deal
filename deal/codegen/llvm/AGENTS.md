# Native LLVM Code Generation

Render the one validated lowered project as one deterministic textual LLVM module (`deal.codegen.llvm.LlvmSemanticEmitter`), and let `deal.module.ProductionProjectEmission` stage it plus the closed `NativeRuntime.FILES` set. Consume only `ExecutableLoweredProject` with its body tables, factory registries and declaration facts: never an AST, a checker object, or a native-only language rule. Keep the closed-set classifier authoritative: every operation kind, payload variant, selector, boundary kind, stdlib operation, failure arm, control selector, call mode, target kind and module-import kind carries exactly one decision in `LlvmStageClassifier`, and a fact outside the staged scalar skeleton raises one `SharedEmissionFailure` with that operation's own origin, which the production arm projects as the single E6005 `SHARED_EMITTER_COVERAGE`. Render only the external references the emitted facts need, each one published by `LlvmRuntimeAbi`: the call-frame and root-frame prologue/epilogue entries, the emitted arm table and its install entry, the one string comparison (`deal_text_compare`), the closed data relation (`deal_data_same`), the two nullish singleton predicates, the type-name projection and the descriptor-driven check. Every generated activation pushes its frame label, enters its root frame with the statically known slot count, and leaves and pops on every exit path; every managed-typed slot that can be live across an allocating call owns one root slot written at definition (a persistent datum through the tag-aware entry, a managed pointer directly, a reference-nullish operand only when it is no nullish singleton), and a scalar or code-pointer slot owns none. Keep `LlvmRuntimeAbi` the single Java mirror of the published headers, in the published declaration order, with `LlvmTypeMapper` the one C-to-IR and descriptor-to-representation mapping, the one pointer-type constructor and the one record-size rule that decides when a published record crosses the C ABI through a hidden `sret`/`byval` pointer; a new runtime entry extends the mirror in the same change. `LlvmSelectorArms` is the single rendering authority of the closed binary and unary selector families: one arm per merged member, with C6's pinned IEEE predicates, the one string-comparison authority, the distinct nullish singleton/tag tests, the closed data relation, managed identity, `fneg`, `xor i1`, the type-name projection and the nominal tag test, and no fast-math flag on any instruction; every runtime-entry arm carries that entry's own result encoding, so `deal_text_compare`'s `-1`/`0`/`1` ordering is compared against zero with the selector's predicate while `deal_data_same`'s `1`-when-equal truth is compared against zero with the inverted one. A `BRANCH` over the logical selectors enters the recorded right-operand block on true for `LOGICAL_AND` and on false for `LOGICAL_OR`, keeps the left operand's value as the skipped path's result, and every rendered call or import tests its carried Error explicitly so the continuation stays reachable. Every failure path returns the enclosing activation's own C4 outcome shape, derived from the lowered function that path belongs to: a `number`, `boolean`, scalar-nullish or `unknown` result keeps its value slot empty on failure instead of degrading to the error-only aggregate, and a returned outcome slot is narrowed back to the SSA spelling only for the managed pointer shapes whose SSA type differs (a `string` and a class instance's own typed record pointer, the builtin `Error` included), because a scalar-nullish aggregate, a reference nullish pointer, a `double`, a persistent datum and a code pointer are already their own slot type. A value whose C3 representation this stage does not construct is never admitted into a position that would need it: `LlvmTypeMapper.isStagedRepresentation` rejects it with its own operation's origin-bearing E6005. A function value is inside that set: it is the managed `deal_fn*` carrier of C5, stored in reference-layout array elements and managed class slots, so `hasDatumForm`/`convertible` admit it into `unknown` and `emitDatum` carries the carrier as the managed `reference` of the function-tagged datum — never a `.text` address — while `typeof` projects that datum's own tag. A check input whose datum can carry that tag (a function value, an `unknown` datum or a nullish position based on either) also carries the carrier's interned signature text selected on the datum's own tag, so no singleton is dereferenced as a carrier, and a check against a function descriptor is a `FUNCTION_SIGNATURE` boundary while every other descriptor keeps `TYPE_DESCRIPTOR`; the checked `as T` assertion is that same rule set, so a function descriptor and a nullish form are renderable assertion targets beside the scalar, container and class ones, and a function datum is projected back onto its own `deal_fn*` carrier by one bitcast. Each binding's declared descriptor comes from the `VARIABLE_DECLARATION`/`VARIABLE_ASSIGNMENT` boundary the lowering emits between that write's value and its commit op, resolved per write and never from a bare value id: the lowering reuses a function-valued identifier's value id for its `BINDING_LOAD`, so a value-keyed lookup would give one binding another binding's declared type. A refined read of that binding projects the value it actually holds onto the refined type's representation through the one datum authority and validates it against the refined descriptor, so a stale refinement fails with the declared arm instead of yielding a base value the binding never held: at the read's own origin on the closed typed boundary, or — when the read feeds a declared host parameter position — at that recorded `HOST_PARAMETER` cell with its one-based index and the crossing's own origin, because the parameter cell is the position that owns that projection and a stale argument must render the shared composite E8010 arm rather than a typed-boundary arm at the argument expression. A synchronous host call renders one `HOST_PARAMETER` check per declared parameter position over its checked argument presentation beside the export's own declared canonical signature, and its result projection is the declared representation's own unboxing once, so a `boolean` result stores the `i1` that projection answers with no second narrowing. A structure op whose recorded child paths all return or throw leaves its join without a predecessor: render that tail as `unreachable` and emit no fall-through epilogue, never an E6005 for a valid program. Emit the closed failure-arm table as data in the published `deal_arm_record`/`deal_arm_table` layout, in the registry's canonical order, and install it in `deal_project_start` before any unit's initialization. The module owns `deal_module`, `deal_export_entry`, the two scalar nullish representations and the six export-surface definitions, defines no process entry and no runtime-owned symbol, and carries the pinned triple, both debug names per function and project-relative file names. Derive every name, order and record from IR facts: no map iteration order, timestamp, absolute path or environment text reaches the bytes. A string literal is immutable static data copied by the `text` group into one runtime string, a template concatenates its recorded fragments in order, and every managed temporary the op itself creates is stored in an activation scratch slot and rooted before the next allocating call. Containers render the `container` group's typed array and insertion-ordered record: `ARRAY_NEW` allocates the array with its persistent element descriptor and appends its validated elements, an index read/write validates finiteness, integrality and bounds through `deal_container_position` before any native offset conversion (a rejected position is the named E8002 arm at the recorded boundary's origin, negative zero addresses zero, and an append commits only after the element check), `length` is the exact count as binary64, a record keeps absence distinct from present-undefined and present-null, and `FOR_EACH` retains its once-evaluated iterable and re-reads the live element count, its live element and its iteration binding at every step (a string traversal yields one single-scalar string per scalar), and an iteration binding is a captured-binding cell whose every iteration allocates its own fresh datum cell — the element is rooted across that allocation — so closures created in different iterations never share one binding. A declared `null`/`undefined` position is a value of its own type, never an absent slot: a field or array element of those types is one reference slot holding the distinct runtime singleton (the `null|undefined` union is that same singleton slot, and its undefined member is admitted through the atom's own base), so class construction, field read/write/delete, array construction/element access, `FOR_EACH` and the JSON construct/read seams all materialize or store the singleton the shared representation names; the optional-read absence projection answers `undefined` whenever the read type admits it, including that canonical union. Each declared class emits one typed instance record (class atom, one presence byte per optional field, one typed slot per declared field), one published `deal_layout` in the emitted install table, one `deal_class_layout` whose field descriptors are the interned atoms, and one `deal_json_class_plan` with its `construct` and `read_field` seams; the read seam identifies the class by its nominal tag alone and answers "this is my class, no such field" for an index outside the declared field list, so a class that declares no field is still identifiable by the host group without one; `deal_class_plans_init` installs the layout table and fills the atoms from `deal_project_start` before any unit initialization. A local class construction validates its supplied fields in literal order through `deal_class_construct` and allocates, tags and publishes the instance only after every check succeeded, the builtin `Error` construction is `deal_error_create_strings` so the constructed instance is the runtime's own record, and a field read projects optional absence to undefined through the presence byte without erasing it (a declared `unknown` field absorbs the nullish members, so its read type is the persistent datum: the present arm stores the loaded `deal_data` slot and the absent arm the undefined datum, and no optional read has a result type without an absence projection). The emitted reference map names the slot itself for a managed-pointer slot — a function-typed slot included, because a `deal_fn*` is a managed object (`LlvmTypeMapper.isManagedValue`), so a function value stored in a declared class field is traced and barriered like any other managed reference — and the datum's own `reference` member (`offsetof(deal_data, reference)`) for an `unknown` slot, never the tag word that slot starts with, so the precise collector traces the stored referent and never `tag`/`reserved` bits; every store into such a slot — at construction, in the JSON `construct` seam and at every later field write — runs the published insertion barrier on the committed slot (`deal_store_barrier` for a pointer slot, the tag-aware `deal_store_barrier_data` for a persistent datum), keeping the traced reference map and the M2 barrier contract in agreement. The generated `C$fromJson`/`C$toJson` walks call the runtime JSON group with the emitted plan and the emitted plan lookup, so the runtime keeps the declaration-order walk, the extra-key/missing-required rules, the cycle check and every failure projection. `LlvmDataValues` is the one native-to-`deal_data` conversion in both directions (branchless, tag-driven, the class atom of a class datum is its instance's own atom, and a builtin `Error` value's managed payload is the `deal_error*` it already holds because the module defines no per-layout record for it), and every datum a cell read, a container or class capture, a dynamic result, a stdlib result or an await completion hands back projects onto its declared representation — a scalar its payload, a managed tag its referent with the value's identity and persistent element descriptor preserved, the two nullish tags their own singletons or tagged struct — while a descriptor outside that set raises one `SharedEmissionFailure` with the offending op's origin; a result-only `void` owns no representation at all, so a stdlib, dynamic or await result of that descriptor skips the unboxing instead of demanding one, and the export record publishes the managed `deal_fn*` carrier of each staged export, which the entry surface invokes through its boxed apply thunk. One imported host declaration module contributes its generated `<host module path>.h` (which declares a class's field-metadata array only when that class declares a field, so a zero-declared-field class publishes its identity with the H2 zero-length-array rule's NULL/count-zero record), one emitted `deal_host_declared_module` record, the origin-carrying `deal_host_load` call at the importing statement's own origin and its host-marked `deal_export_entry` array; a synchronous host call renders the export's own declared canonical signature (the same text the import's export record carries) beside the checked argument presentations whose declared parameter cells each run their own `HOST_PARAMETER` check at the call origin, so the runtime reads the declared result position from that signature's result atom and a function-typed result crosses as that function descriptor; the import's `deal_module` record becomes visible in the importing unit's `finish` segment together with that unit's own record, so a unit whose initialization fails publishes no host export surface, and the runtime never reads or builds a module layout. A recorded `CALLBACK_INVOKE` emits one module-level host-driven re-entry entry with default linkage under the deterministic C identifier `deal_callback_<moduleIndex>_<opId>`; it answers the runtime's `deal_host_result` through `deal_host_callback_invoke` over the recorded function's own boxed apply thunk and the function value its export record published, so a statically linked host unit re-enters DEAL code with crossing carriers and receives the same relay-or-discard failure record `deal_apply` answers. Calls, closures and modules: a captured or reassigned binding generation is one heap cell allocated exactly once (parameter and captured-catch cells are published from the incoming argument or caught Error; their own `BINDING_ALLOC` allocates nothing), read and written through the tag-aware cell entries and rooted by its slot; `CLOSURE_NEW` is the managed `deal_fn*` carrier of the generation-pinned capture list with its emitted boxed apply thunk (`T<id>`), `RECURSIVE_GROUP_INIT` allocates every member cell before it publishes any member closure and each member binding's declared descriptor is the descriptor of the function the group publishes into that member's slot, so the member's cell is a `deal_fn*` cell like any other captured binding generation, a statically resolved call is a direct call to `F<id>` with the callee's own environment, a dynamic call validates the carried signature atom at the recorded call signature (the one E8010 arm) and invokes the thunk with the boxed argument presentations, the thunk being the carrier's dispatch shim rather than a DEAL activation — it pops its own frame label before the dispatched body runs, so one activation contributes one Error frame, and a `FUNCTION_ADAPT` is one adapter closure (`A<opId>`) retaining the once-evaluated source function in a private immutable cell, re-validating its signature and applying it with the target's leading parameters. Its dispatch shim pops its frame label before applying the source, preserving exactly the DEAL activation frames. The retained-value cell is live across `deal_fn_create` and owns a root slot. A unit's initialization is depth-first in imported order, once only, records its sticky carried failure in its own module record and publishes its export values only after success; an imported function value is read from the emitted export table, and module-level cells and export slots are static roots. `STDLIB_CALL` passes the closed operation id, the boxed argument presentations and the call origin to `deal_std_call`, which owns the `STDLIB_PARAMETER`/`STDLIB_RETURN` crossings, and a stdlib function value is one per-unit carrier over the emitted `S<ordinal>` thunk. `ASYNC_START`/`AWAIT` emit the C7 operation-record, token and await-origin completion calls against the published `async.h` declarations, a cross-module callee resolves through the payload's own external async link to the exporting unit's lowered body, and a dynamically or indirectly checked callee carries the same `FUNCTION_SIGNATURE` signature-atom check as the dispatched call before the operation record exists; a statically resolved callee that is a declared host async export is first projected into that export's own carrier through `deal_host_export_value` with the call's declared canonical signature, so the runtime's start routes the carrier to the token-bound host crossing. `deal_async_export_invoke` branches on the record's own async marker and host marker: an async host entry invokes `deal_async_export_call_host` with the record's resolved export record, an async DEAL entry invokes `deal_async_export_call` with the export's function value, and every other record keeps the synchronous `deal_export_invoke`, so an async export is pumped to completion and its completion is checked at the result atom of the record's own descriptor. The async runtime group's definitions are published, so an async project links and runs.
