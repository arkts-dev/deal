# Modules

Own module resolution, dependency order, checked-project orchestration, and identity assembly. Complete and validate the graph before lowering or publication. Preserve phase boundaries and deterministic order. Construction entries are allocated per declared class occurrence (declaring module, then canonical class identity), and the dependency graph's recorded contextual class-literal provider aliases are republished into the checked project before the one lowering. An import symbol carries the imported module's own declared function symbols beside its class symbols, so a call argument's construction context resolves the callee parameter's exact declaring class provider through the parameter's own annotation in the callee's declaring module, and a function-typed callee's own bound parameter carrier supplies the same context. A class literal's construction follows the checker's recorded construction declaration: a literal laid out by this module's own declaration keeps the same-module resource and plan even as an argument of an imported callee, a literal whose checked context names an import (an enclosing annotation, an enclosing class field's declared annotation, an imported callee's parameter, the declared return annotation, or the literal's own bound carrier) is attributed to that import's own declaration (a same-identity local declaration of the same name never captures an imported construction), and the exact declared class symbols of every checked expression travel to the one lowering with the checked facts. Every recorder seat additionally consumes the whole-project provider index (each resolved module's own planning snapshot, keyed by its dotted module path): an exact checked declaration reached only through an imported declaration's own field, parameter or return annotation resolves that module's declaration for its resource, plan occurrence and runtime edge, so an identity-equal sibling import that shares the canonical module identity — or an import that carries no declaration of the demanded class — is never selected as the provider. Exported class types and checked class expressions carry the declaring module's own wiring key as their defining provider, so a consumer's assignment boundaries keep same-spelled sibling declarations distinct instead of retagging a value (the crossing is the checker's named E3019). Semantic routes consume validated project IR; never silently fall back within a compilation. `ProductionProjectEmission` owns the release-owned production arm: one project lowering, the pre-emission closure guard, and the one production project artifact per target with its per-module `.deal.map.json` source-map sidecars (the v1.3 default; the accepted `--source-map` spelling selects nothing) plus the complete deployment copies — a runtime or spec-listed stdlib implementation the resolved distribution surface does not provide fails the compile; it reads no routing, planner, registry, retained-backend, or counting surface.
