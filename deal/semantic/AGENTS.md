# Semantics

Own backend-neutral checked-project lowering and shared runtime meaning. Encode evaluation order, boundaries, failures, calls, classes, modules, and stdlib behavior once. Semantic IR is production on every backend; the AST-consuming emitters are retired. Complete constructs vertically. An imported-class construction or field operation resolves the exact declaring provider: a class literal resolves the checker's recorded construction declaration first (the unit's own layout for this module's declaration, otherwise that declaring occurrence's registered construction entry and shared facts) before the recorded contextual provider alias, and a field operation records the exact declaring provider's construction entry in its payload (resolved from the checker's per-expression declaration — a call result's or inferred binding's own bound carrier included — and the project index) so read, write and delete use the declaring declaration's layout — never a unit-local mask or an identity-keyed first match. The canonical class identity names the defining file, so a valid project carries exactly one declaration per identity and the identity-keyed route selects it exactly; the defensive multiple-declaration rules stay fail closed for a carrier-shared identity (a harness-synthesized identity, which valid source never produces): a class literal whose identity carries more than one declaration and records no resolvable declaration fails closed with a named E6005 even when the unit carries a local layout, and an unrecorded field operation of such an identity fails closed with the same named rule that retains the offending operation's own source origin rather than selecting a first alias; the generated JSON plan table carries the unique plan-bearing (`@jsonable`) declaration's structural layout under the canonical class identity, a nested JSON link whose declared type resolves another declaration of the identity and any identity carrying more than one plan-bearing declaration fail closed with the same named rule; the generated JSON plan key admits no declaration-file nested class (a declaration module carries no implementation lowering, so that nested link stays fail closed with the same named rule on every backend), and the Oracle's construction/field layout resolution, its JSON plan-owner layouts and its instance-keyed layouts follow the same exact selection. Project seed coherence resolves implementation classes through exact interface/module identity without fabricating declaration seeds; declaration seeds also agree with field operations and optional-read descriptors, including private classes with no construction. The construction validator's field-read rule and the declaration-seed field-operation check both derive the read result from the layout's own canonical optional-read projection, so an optional field declared `null` reads as the `null` atom (its two states are the missing and present-null reads, both language `null`), an optional `T` reads as its one nullable wrap, and a read publishing any other wrapped descriptor fails the pinned shape rule instead of crashing. The bindings-production and class-construction owners admit the same complete facts on the typed and text surfaces: closure/record capture links, the complete registration variants against their producing operations, parameter/import facts against real allocations, and the factory/layout/construction-entry agreements reject identically instead of repairing content. The composed per-module production admission consumes exactly the unit's owned companion records: a supplied body-table, parameter/import or class-factory view that differs from the unit rejects with E6005 `PROJECT_VIEW_MISMATCH` before any success, and a content-equal detached view is replaced by the owned record. The sole release-owned profile is DEAL_V1_4_BINARY64 with V1_4_ACTIVE; retired signed-integer profiles reject, never alias. The one project lowering threads the invocation's carried `semanticProfile` into every unit and project constructor, every comparison fact and every admission gate, so the produced unit/project profile and their lowering-context hashes derive from that carried value. The bindings owner's `IMPORT_OCCURRENCE_CORRELATION` rule correlates every function-typed HOST import read with the alias cell of the `MODULE_IMPORT` occurrence that materialized it, so the selectable occurrence is recorded once per source import and never re-derived from a module/name lookup. A function-typed binding whose declaring function body assigns that name anywhere — the assigning statement in a nested function body included, and independent of walk order — carries no statically tracked allocation identity: every read of it publishes the producer rule's dynamic materialization, and every call or `await` through it records the loaded value as the closed `Dynamic` callee, so a closure body, a nested closure body, a re-evaluated loop condition, a post-branch call, an alias read, an imported-value read and a host-origin read all observe the current binding (docs/spec-v1.4.md §Closures and captured variables), while a never-assigned binding, a declared-name call, direct and mutual recursion, and the arity-extension adapter's own statically fixed or runtime-resolved source selection keep their landed callees. `HostDeclarationSurface.sortedByName` is the single ascending-name selection of JS declared-export validation/raw reads; the declaration-ordered provider facts stay untouched. Module-level class declarations register their structural layouts, generated JSON helpers and exact provider metadata before function bodies lower. Class field initializers are invalid syntax and produce no AST expression or semantic operation. Every nonoptional field is required-present independently of nullability; checker, typed/raw/text admission and executor reject omitted required values, including builtin Error code/message. Each provided field owns one declaration-order CLASS_LITERAL_FIELD boundary. Missing optionals stay absent. JSON decoding rejects missing required keys, extra keys and failed nested values without executing defaults, constructor hooks or factories. Host construction uses the declared layout rather than any host defaults map. An arity-extension adapter whose source expression is re-evaluated per invocation (a call result, member read, conditional or conversion — the `REEVALUATE_THUNK` capture mode) resolves its source value's execution class at execution: the adapted source's produced value is its final producing op (a trailing non-producing call companion, such as the call's return boundary child, never selects it), a synchronous invocation records the closed dynamic callee arm's three return cells — one per runtime source class — and an async target starts the closed dynamic async arm over the adapter's published identity with the single caller-side DEAL-body task cell. An `await` call-result adapter source is the declaration-site VALUE (the suspension delivers the function value once, and a synchronous re-executor can never await): a synchronous target keeps the recorded adapter call over the carrier with the runtime host source's family return cell, and an async target records the runtime-resolved nested source start — `Dynamic` over the retained value identity, `ELIDED_BY_ADAPTER`, the single caller-side DEAL-body task cell — inside its adapter-inner task. A call-preserved null-narrowing refinement (`docs/spec-v1.4.md` Nullable semantics: calls never invalidate a refinement, so a capturing closure can clear the binding behind it) is validated at its consumption, not at the read: `SemanticLowerer.lowerOperand` publishes one `BOUNDARY(NARROWED_READ)` over each refined identifier read in an operator operand position (the arithmetic, comparison, logical and string-concatenation operands, the template interpolations included), in an index read/write/delete receiver or key position (the array and table index arms, each receiver and key lowered once through that helper), in a table member read/write/delete receiver position (the `MEMBER_READ`/`MEMBER_WRITE`/`MEMBER_DELETE` operation dereferences the admitted value, and the nested member read of an address chain is admitted where it stands), and in a `.length` receiver position (the array length arm, whose `ARRAY_LENGTH` consumes the admitted value) and as a `for-of` iterable (both the array and string arms: the `FOR_EACH` consumes the admitted value, so a capturing closure that cleared the binding reports the typed-boundary failure before the loop's initialization dereferences the carrier and the iterable still completes exactly once), and as a `has` receiver (the `HAS_FIELD` presence read consumes the admitted value — the refined class descriptor's nominal check — so a cleared binding reports the typed-boundary failure instead of reading presence off it) with the read's own origin and the refined descriptor, the condition positions (`if`/`while`) validate in place, and the logical branch's right operand publishes the caller's pre-allocated condition identity instead of a second value; the index admission is the chain's receiver/key child itself, so the chain's length/normalize/commit children and the commit's resolved receiver/key reference the admitted value while the closed A-D9 child shape (count, positions, parentage) is unchanged, and an index read's `INDEX_READ` container and normalize key are the admitted values, and a `.length` receiver or for-of iterable admission publishes its own value so the `ARRAY_LENGTH` op or the `FOR_EACH` reads that admitted value instead of the unadmitted read; every other position (a class-field receiver, whose own `UNTYPED_CLASS_INPUT` child already validates it, included) is a typed boundary owned by its own cell and keeps its recorded projection — the array-element cell's E8003 arm included — and a declared nullable read, a null test and a function-boundary read are never rewritten. The builtin `Error` value keeps one identity across the oracle's throw/catch: a constructed Error's THROW binds the synthesized failure to the value itself (so the catch binding is the thrown instance, a rethrow republishes the carried failure with the value's current code/message, and a handler's replacement adopts its own carried identity while linking the caught failure as cause), and `ErrorValue` is a reference-identity comparison operand exactly like a class instance. The catch variable is an ordinary mutable lexical binding of the catch block's own scope (docs/spec-v1.4.md Closures and captured variables; try / catch): the full-program walk registers its generation-0 incarnation in the catch block's own scope frame before the catch body lowers, so a direct catch-variable assignment resolves that cell through the ordinary address chain, a closure created in the catch block registers the binding as a capture of its detached body (the catch block's producing BINDING_ALLOC is the incarnation the capture resolves to), and the capture-driven cell kind makes a captured catch incarnation a shared cell while an uncaptured one stays direct; the semantic oracle allocates that cell freshly at each catch execution (the catch block's leading BINDING_ALLOC never re-allocates it), so a closure created in an earlier catch keeps that execution's caught value exactly as the emitted per-execution cell does. Nested catches and block declarations shadow the name by the ordinary innermost-frame rule, and a closure parameter of the same name captures nothing. A bare identifier assignment target claims the ASSIGNMENT construct row and never the IDENTIFIER read row, because the write position produces the chain's BINDING_STORE commit and no BINDING_LOAD, while still carrying its checked type. Architectural direction never expands assigned task scope. `int` and `number` are ordinary value identifiers: every callable needs its real producing operation and ordinary binding, capture and adapter rules. No conversion seeds or intrinsic call operations exist. Adapter creation wiring admits supplied class fields only, with no initializer publisher or default-field boundary exception; ordinary return, assignment, host/stdlib and async adapter rules remain intact. Array slot trace atoms render the raw binary64 index with canonical hexadecimal spelling on every consumer, preserving signed zero without host decimal-format differences.
