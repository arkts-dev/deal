# Semantics

Own backend-neutral checked-project lowering and shared runtime meaning. Encode evaluation order, boundaries, failures, calls, classes, modules, and stdlib behavior once. Semantic IR is production on every backend; the AST-consuming emitters are retired. Complete constructs vertically. Every module-level class declaration's structural facts (field layout, field descriptors and exact declaring field providers) are hoisted in declaration order before any body is lowered (docs/spec-v1.3.md §Name resolution: class/function declarations are hoisted, function bodies and class fields may reference classes declared later), so an earlier body's construction or field operation of a later-declared class resolves the same declaration facts as a later one; a forward construction produces that declaration's own ops (its detached default thunks, its exported factory and its generated JSON helpers) once at the module-init top, and the declaration walk then produces nothing second. An imported-class construction, default or field operation resolves the exact declaring provider: a class literal resolves the checker's recorded construction declaration first (the unit's own layout for this module's declaration, otherwise that declaring occurrence's registered construction entry and shared facts) before the recorded contextual provider alias, and a field operation records the exact declaring provider's construction entry in its payload (resolved from the checker's per-expression declaration — a call result's or inferred binding's own bound carrier included — and the project index) so read, write and delete use the declaring declaration's layout — never a unit-local mask or an identity-keyed first match. A class literal whose identity carries more than one declaration and records no resolvable declaration fails closed with a named E6005 even when the unit carries a local layout, and an unrecorded field operation of a same-identity sibling pair fails closed with the same named rule that retains the offending operation's own source origin rather than selecting a first alias; the generated JSON plan table carries the unique plan-bearing (`@jsonable`) declaration's layout and defaults under the canonical class identity, a nested JSON link whose declared type resolves another declaration of the identity and any identity carrying more than one plan-bearing declaration fail closed with the same named rule; the generated JSON plan key admits no declaration-file nested class (a declaration module carries no implementation lowering, so that nested link stays fail closed with the same named rule on every backend), and the Oracle's construction/field layout resolution, its JSON plan-owner layouts and its instance-keyed layouts follow the same exact selection. Project seed coherence resolves implementation classes through exact interface/module identity without fabricating declaration seeds; declaration seeds also agree with field operations and optional-read descriptors, including private classes with no construction. The bindings-production and class-construction owners admit the same complete facts on the typed and text surfaces: closure/record capture links, the complete registration variants against their producing operations, parameter/import facts against real allocations, and the factory/JSON-default/construction-entry agreements reject identically instead of repairing content. The composed per-module production admission consumes exactly the unit's owned companion records: a supplied body-table, parameter/import, class-factory or JSON-default view that differs from the unit rejects with E6005 `PROJECT_VIEW_MISMATCH` before any success, and a content-equal detached view is replaced by the owned record. The one project lowering threads the invocation's carried `semanticProfile` into every unit and project constructor, every comparison fact and every admission gate, so the produced unit/project profile and their lowering-context hashes derive from that carried value. A function-value adaptation whose source expression is re-evaluated per invocation (a call result, member read, conditional or conversion — the `REEVALUATE_THUNK` capture mode) resolves its source value's execution class at execution: the adapter's produced value is its final producing op (a trailing non-producing call companion, such as the call's return boundary child, never selects it) and the invocation records the closed dynamic callee arm's three return cells, one per runtime source class. The bindings owner's `IMPORT_OCCURRENCE_CORRELATION` rule correlates every function-typed HOST import read with the alias cell of the `MODULE_IMPORT` occurrence that materialized it, so the selectable occurrence is recorded once per source import and never re-derived from a module/name lookup. `HostDeclarationSurface.sortedByName` is the single ascending-name selection of JS declared-export validation/raw reads; the declaration-ordered provider facts stay untouched. Architectural direction never expands assigned task scope. Keep this file always synchronized with code.
