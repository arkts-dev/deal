# Semantic IR

Define the validated, executable, backend-neutral compiler contract. Admit no AST or checker-owned objects; keep IDs, descriptors, payloads, ordering, and serialization deterministic. Evolve lowerer, validator, Oracle, every emitter, and tests atomically. The typed record surface and the canonical text surface feed one complete raw fact model through one composed admission: registry identities, body membership, the module-init/export-plan links, functions/captures, the complete binding variants (including the closure and adapter registration links) and the class-construction/default facts reject with the same first failure on both surfaces. `RawUnitMaterializer` is the canonical raw-to-typed inverse of `RawUnit.fromTyped`; it grants no authority and fails closed on an undecodable recognized position. A standalone unit runs the applicable local predicates and rejects every fact that requires the project's provider context (a CLASS_NEW under an imported/declared default owner, a SHARED_BODY external function of another module, an externalEntryRef naming another module) with the first E6005 at the referring subject; the complete-project surfaces resolve exactly those links from the supplied closure (the class owner runs where the carried interface index, seeds and surrounding modules supply the provider join, resolving a SHARED_FACTORY construction and a FIELD_READ/FIELD_WRITE/FIELD_DELETE by its recorded construction entry for an identity that carries more than one declaration (a carrier-shared identity a valid project never produces, because the canonical identity names the defining file), failing a record-less field operation of such an identity closed with the named rule, and validating a nested `@jsonable` link through the recorded plan owner of the multiple-declaration identity instead of a unit-local sibling). The typed and text project surfaces share one framing admission (module-map key/identity agreement, the carried profile, index coverage and provider classification, required in-project implementation providers and the dependency order of the resolved imports), and the production composition keeps its pinned per-module order (common-admission head, address chain, control flow, bindings, class construction) with each owner running once over exactly the unit's owned companion records. The carried `semanticProfile` is the single-profile owner's value at every constructor, validator and guard: the admitted name is derived from that owner, the lowering-context hash is recomputed from the carried active profile with the supplied capability-registry hash, and a carried profile that disagrees with the supplied comparison facts or with the project profile rejects with `R-PROFILE` — no path substitutes a removed v1.2 value or projects a hard-coded profile. `FOR_EACH(ARRAY_VALUES)` evaluates its iterable once (the `NARROWED_READ` admitted value when the iterable is a refined read, never a second read), retains the alias and traverses increasing live positions: the first absent position (a deleted slot or a position past the live end) stops the iteration, a contiguous append is visited, and a present wrong element still fails its terminal check — never skipped. A function-typed HOST import read records the owning source import occurrence's alias cell on its `HostFunction` binding (`importCell`), and `BindingsProductionValidator`'s `IMPORT_OCCURRENCE_CORRELATION` rule requires the cell to be initialized by exactly one `MODULE_IMPORT` completion resolving that host module (a STDLIB once-only surface records none); a missing or mismatched correlation fails E6005 at the read's own origin, never a module/name fallback. The raw non-object host result's unlocated projection is the declared `HOST_LOAD_RAW_SHAPE` arm (module-less text, pinned `table` expected, the JS diagnostic-kind (`$kindOf`) actual over the values the guard rejects, no location), distinct from the located declared `HOST_LOAD` arms. Every production backend consumes this IR; the AST-consuming emitters are retired. The closed boundary-kind set carries `NARROWED_READ`: the operand, condition and value-consumer (index receiver/key, table member receiver, `.length` receiver, for-of iterable, `has` receiver) position's validation of one identifier read whose checked type is a null-narrowing refinement of the binding's declared nullable type. Its cell is the descriptor-kind policy of its own descriptor (E8001 for a value descriptor, the signature row for a function descriptor) and its input must be a `BINDING_LOAD` result — the refinement claim is about a binding, never an arbitrary value; `R-BOUNDARY-TRIPLE` fails closed otherwise. A free `BOUNDARY` may publish its own result (the operand position's validated value, so an address chain's operand closure executes the check at its consuming child's position), publish a caller-supplied consumer identity (the slot-threading operand's pre-allocated condition — the result is then the input's own identity), or validate its input in place (the condition position, whose `LOOP(FOR)` re-production keeps one condition identity); a value-publishing cell may also be an index chain's receiver or key child, where the chain's `ARRAY_LENGTH`/`INDEX_NORMALIZE`/commit children and the `INDEX_READ` container reference the admitted value, or a `.length` receiver or for-of iterable, where the `ARRAY_LENGTH` op's receiver or the loop's `FOR_EACH` iterable is the admitted value, or a `has` receiver, where the `HAS_FIELD` presence read's receiver is the admitted value (the refined class descriptor's nominal check), and every consumer publishes such a child's result (the three chain-boundary arms, the length op, the for-of loop, the presence op and the Oracle's chain executor included).
