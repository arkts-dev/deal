# Amend

Client-facing amendment of checked DEAL source. Two entry paths: direct (`applyChecked`, one ChangeSet, commit or reject) and scoped repair (`stageChange`, `expandRepairScope`, `applyRepairTransaction`, per-slot, grant-limited). Edits are revision-pinned; a target requires the fingerprint from `inspect` or `inspectChange`. Identities are compiler-issued, revision-scoped, never persisted, never written to source. `ModuleResolver`, `SourceAdapter`, and `CandidateValidator` are the seams; consumer framework checks enter through `CandidateValidator` inside the transaction. Scope is one module, front end only: never invoke the project orchestrator, never claim the project builds. Emitted source is a candidate; the checker stays authoritative. Declaration-reference discovery traverses computed object keys before values so key-only dependencies remain visible. Correlate diagnostic secondary ranges only with exact local declaration targets; related identities never expand edit authority. Diagnostic JSON follows `docs/diagnostics-protocol-v3.md`. Attribute nested callable/class diagnostics to the smallest inspected semantic node; read-only owners carry no new operations and remain distinct from existing editable scopes.
