# Frontend Conformance

Test lexing, parsing, checking, and module resolution independently of backend execution. Pin exact compile outcomes, diagnostics, and ranges against the specification. Keep support modules subordinate and cover accepted plus rejected forms. A catch-binding case pins the catch identifier as a fresh `Error` binding: an int-, string- or null-refined outer binding of the same name never types the catch read, the Error transfer and its message read are accepted beside the rejected Error-to-string and Error-to-int transfers, and the outer refinement is usable again after the catch unless a try-block assignment, a catch-block assignment or an `await` invalidated it — a shadowing try-block declaration does not, and a try/catch nested inside an enclosing try block preserves the outer refinement while reassigning its own catch binding, whereas a try-block assignment inside that nesting still reverts it. A try-binding-identity case pins the assigned set by resolved binding: a try-local shadow declaration (with or without a write to the shadow) and an uncalled nested function expression's or declaration's write keep the enclosing non-null and null-branch refinement, while a nested try block's assignment still reverts it.
