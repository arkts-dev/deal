# Runtime Conformance

Assert observable values, effects, errors, source origins, identity, and evaluation order across applicable backends. A class-identity case pins the exact declaration atom: the canonical identity carries the defining file, so same-named sibling files never share an atom. Ordinary identity-boundary failures name both atoms; checked extraction uses E8001 typed-kind with the actual atom, explicit target and independently exercised valid declaration controls. The same-named-sibling controls split into error arms and one runtime-ok control, and the runtime-ok control's sidecar is the oracle at the LuaJIT and JVM production terminals (Node executes it in the JS lane): each backend runs the fixture's own terminal and must render the pinned exit code and transcript byte-exact, so a correct-provider value a backend rejected or mis-tagged fails instead of passing the error-only cases. Execute production artifacts and keep helpers deterministic. Add cases that expose semantic-emitter divergence; never bless AST-only behavior. Host-carrier cases drive one lane protocol on every claimed backend: the sidecar pins the LuaJIT, JVM, and JS backends, the entry terminal runs once, then each declared zero-arity assertion export runs in declaration order on the LuaJIT and JVM production artifacts (Node executes them in the JS lane). `CorpusConformanceTest` discovers all runtime sidecars once and consumes every declared production-backend expectation. Its shared parsed invocation plan runs main once, then eligible zero-arity exports in declaration order; receipts reconcile starts/completions outside observable transcripts. A negative fixture with exported probes has an empty main and exactly one failing probe; independent throws require separate fixtures. Computed results need local assertions. Missing tools, exports, completions, or host-implementation triplets fail. Keep focused consumers and their distinct assertions; broad corpus execution alone never establishes equivalence for removal. Class fields are structural: provide every nonoptional value, including nullable and callable fields. Preserve freshness through separately evaluated literals and alias identity through explicitly provided references; no initializer supplies omitted fields. Construction-failure cases retain provided-expression effects but cannot replace an existing target with a partial instance. Numeric cases assert binary64 values, signed zero and nontrapping arithmetic. JSON numeric text may vary when it roundtrips to the same binary64 value; pin structural content and decoded values, with exact zero serialization. JSON fixtures use unknown stringify inputs: arrays, null and nominal class instances serialize rather than failing a retired Record-only parameter check. Nonfinite numbers substitute null; functions and undefined omit from objects, substitute null in arrays and yield undefined at the top level. Keep cycle failures and top-level parse Record rejections exact, with migrated source coordinates. Retarget removed arithmetic failures to surviving failures when preserving catch/control-flow/source-origin consumers. Catch bindings start unknown; assert Error or refine inside a matching instanceof branch before member reads. Catch-shadowing cases preserve outer nullish refinements, nested catches/blocks, renamed bindings, replacement identity and parameter shadowing; do not depend on post-termination guard narrowing outside the specified branch model. Presence fixtures use Object.hasOwn independently from undefined/null reads; no presence test grants value narrowing. Record field reads retain unknown until an explicit checked assertion; do not restore contextual coercion from an annotated binding or condition. Record deletion tests separately assert missing-key presence and undefined, keeping present null distinct. Void completion controls distinguish bare/fallthrough void from explicit null results.
