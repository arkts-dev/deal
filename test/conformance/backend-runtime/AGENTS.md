# Runtime Conformance

Assert observable values, effects, errors, source origins, identity, and evaluation order across applicable backends. A class-identity case pins the exact declaration atom: the canonical identity carries the defining file, so same-named sibling files never share an atom and every crossing names both. The same-named-sibling controls split into error arms and one runtime-ok control, and the runtime-ok control's sidecar is the oracle at the LuaJIT and JVM production terminals (Node executes it in the JS lane): each backend runs the fixture's own terminal and must render the pinned exit code and transcript byte-exact, so a correct-provider value a backend rejected or mis-tagged fails instead of passing the error-only cases. Execute production artifacts and keep helpers deterministic. Add cases that expose semantic-emitter divergence; never bless AST-only behavior. Host-carrier cases drive one lane protocol on every claimed backend: the sidecar pins the LuaJIT, JVM, and JS backends, the entry terminal runs once, then each declared zero-arity assertion export runs in declaration order on the LuaJIT and JVM production artifacts (Node executes them in the JS lane). `CorpusConformanceTest` discovers all runtime sidecars once and consumes every declared production-backend expectation. Its shared parsed invocation plan runs main once, then eligible zero-arity exports in declaration order; receipts reconcile starts/completions outside observable transcripts. A negative fixture with exported probes has an empty main and exactly one failing probe; independent throws require separate fixtures. Computed results need local assertions. Missing tools, exports, completions, or host-implementation triplets fail. Keep focused consumers and their distinct assertions; broad corpus execution alone never establishes equivalence for removal. A catch-binding narrowing case runs its reads on every declared backend: the catch identifier's own Error transfer and message read under an int-, string- and null-refined same-named outer binding, the outer refined read after the catch, nested catches, nested blocks, renamed and unrefined catches, a reassigned catch binding, a try/catch nested inside an enclosing try block that reassigns its own catch binding and keeps the outer refinement after the inner and the outer catch, and a parameter refinement, each asserted by the fixture's own terminal so a backend that rejected a valid Error read fails instead of passing an error-only case.
