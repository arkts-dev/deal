# Conformance

Maintain specification-indexed frontend and runtime cases with deterministic metadata and exact outcomes. Shared cases run every applicable production lane. A class-identity case pins the exact atom of the declaration it names: the canonical identity carries the defining file, so same-named sibling files are distinct declarations and a crossing names both atoms. Fixtures should expose semantic-IR gaps without blessing retained behavior. Keep companions explicit and focused. A case that reassigns a function-typed binding pins the current-value dispatch the spec requires of reads: the closure body, a nested capture, the copied alias, the repeated loop condition and the branch, imported and host-origin call paths, beside the never-assigned, recursive and arity-extended controls that must keep their statically resolved callees. A function-valued C-style for counter is a loop-head declaration like any other `let`: the case pins the declaration initializer, the update's reassignment and the body assignment (each observed through the current binding), the captured per-iteration values, the alias and returned-closure initializers, the arity-adapted counter, the continue/update order and the break skip, the recursive and mutually recursive function values, and the loop-head scope, each bounded by a visit guard so a stale callee or a lost carry fails the exact count. A for-of case pins the `let` iteration binding as one mutable cell per iteration: the body's assignment, a capturing closure's read and its own store, and each iteration's independent cell, beside the traversal controls that must survive the mutation (the iterable evaluated once, an appended array's live length and contents, no redirection after the iterable variable is reassigned, break/continue after the mutation, and an awaited resumption in an async body). Keep this file always synchronized with code.
