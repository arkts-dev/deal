# Conformance

Maintain specification-indexed frontend and runtime cases with deterministic metadata and exact outcomes. Shared cases run every declared production backend through `CorpusConformanceTest`, using one discovery/preparation/verdict owner and backend-specific artifact launch. Exact rejection is distinct from execution; missing tools and incomplete invocation receipts fail. Bound native-library bootstrap like other subprocesses. A class-identity case pins the exact atom of the declaration it names: the canonical identity carries the defining file, so same-named sibling files are distinct declarations and a crossing names both atoms. Fixtures should expose semantic-IR gaps without blessing retained behavior. A fixture's runtime value must arrive through a specification-admitted shape: a table read nested in an array/class literal element or a template interpolation part is E3003 at the read, so a dynamic value that a runtime case needs reaches its use through an explicitly typed intermediate (or the read's own admitted position) rather than through a literal element. Keep companions explicit and focused. A case that reassigns a function-typed binding pins the current-value dispatch the spec requires of reads: the closure body, a nested capture, the copied alias, the repeated loop condition and the branch, imported and host-origin call paths, beside the never-assigned, recursive and arity-extended controls that must keep their statically resolved callees. A function-valued C-style for counter is a loop-head declaration like any other `let`: the case pins the declaration initializer, the update's reassignment and the body assignment (each observed through the current binding), the captured per-iteration values, the alias and returned-closure initializers, the arity-adapted counter, the continue/update order and the break skip, the recursive and mutually recursive function values, and the loop-head scope, each bounded by a visit guard so a stale callee or a lost carry fails the exact count. A for-of case pins the `let` iteration binding as one mutable cell per iteration: the body's assignment, a capturing closure's read and its own store, and each iteration's independent cell, beside the traversal controls that must survive the mutation (the iterable evaluated once, an appended array's live length and contents, no redirection after the iterable variable is reassigned, break/continue after the mutation, and an awaited resumption in an async body). A for-of iterable that is a call-preserved null-narrowing refinement pins the iterable admission on both carriers: the cleared binding raises the canonical catchable E8001 at the iterable read with zero body visits, and the valid string refinement keeps the once-admitted value through a later closure replacement or body clear, an empty string, astral and combining scalars, each iteration's fresh captured binding, break/continue and an awaited resumption inside the loop body. A `throw` whose operand is a call-preserved null-narrowing refinement pins the operand admission on every backend: the cleared binding raises the canonical catchable E8001 at the operand read's own range with the class descriptor's expected/actual tuple and the caught flag asserted after the try, through the direct, parenthesized and caller-catch forms and inside an async body, while the escaping async export reaches the production invokers as the DEAL error rather than an infrastructure failure; the unchanged non-null `Error` keeps its identity and a handler's field write across the throw, a caught error rethrows unchanged, and the operand expression evaluates exactly once. Keep this file always synchronized with code.
