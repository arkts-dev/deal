# Host Fixtures

Keep declaration files and JavaScript, Java, or Lua implementations behaviorally identical. Pair valid and invalid boundary cases; distinguish missing exports, invalid values, async shape, and nullability. Fixtures are harness companions, not discovered cases. Host-carrier fixtures declare their classes in the declaration file and carry the same canonical identities, defaults, function wrappers, and async operations in all three implementations: a class value crosses with its declared top-level fields, a function value is the documented wrapper, and an async export returns a real backend async operation. The corpus lane materializes every declaration under its dotted external identity, so an implementation that names a generated class or function carrier writes that identity text, and any harness project that compiles these implementations imports the same declarations under the same identity form. Numeric declarations and generated JVM carriers use binary64 `number`/`double`, including function signatures and arrays. Host transcript formatting must not infer a language integer kind from a Java box or an integral payload. Keep this file always synchronized with code.
