# JSON Slice Behavioral-Pin Absorption Record — ISSUE-0360

Sequencing-step-3 migration (pin-before-delete) over the passable portion of
the JSON slice corpus. Every pin of every case of all 24 JSON files under
`test/conformance/fixtures/` carries exactly one disposition here; no pin
lacks a disposition. The three fully-absorbed files are deleted; the
remaining files keep their blocked cases (their absorbed cases are deleted
per-case).

## Disposition classes

- **ABSORBED** — the pin's destination `.deal` fixture passed the
  differential gate invocation before the JSON case was deleted
  (runtime destinations: all three lanes byte-exact; frontend
  destinations: the backend-neutral frontend comparison). Evidence:
  the committed full three-lane gate run log
  `test/conformance/json-absorption/gate-pass-log.txt` (one `VERDICT` line
  per fixture per backend; `frontend OK` / `compile pin OK` lines for the
  frontend corpus). The run reproduces the pinned pre-flip accounting
  exactly: luajit 268/33, jvm 194/107, js 269/32, 0 classification
  failures, 190 frontend compiled, 4 compile pins compared. Every
  absorbed destination below is `PASS` on all three lanes (or `frontend
  OK`/`compile pin OK`) in that log; no deletion happened without the
  logged pass.
- **BLOCKED** — the destination cannot yet pass all three lanes pre-flip
  (a real backend gap) or is retained by a release-owned catalog row; the
  JSON case STAYS in the JSON corpus and stays in `run_tests.sh` until
  T14's residual absorption. Every blocked entry names a destination and
  a tracking issue.
- **IR** — `irContains`/`irNotContains` pins, already migrated to the
  golden-IR suites by T11 (ISSUE-0358): the per-pin golden destinations
  are recorded in `test/conformance/ir-pin-migration-record.md`; the
  golden suites run in `run_tests.sh` (gate-manifest `IrGoldenTest`).
- **DETAIL** — backend-internal rejection detail text; the T12
  unit-test destination is named (the `testUnsupportedConstructsRejected`
  pattern / the existing `JvmBackendTest` E6000 anchor).
- **DROPPED** — recorded with a per-pin rationale (empty
  `expectedNotOutput` lists assert nothing; JVM stack-diagnostic
  exclusions are subsumed by the destination's exact transcript).

Issue key: ISSUE-0111 (signed-int32/bytes known-fails and legacy
safe-range families), ISSUE-0276 (JVM lane failures — backend completion),
ISSUE-0277 (JVM std/json, bytes, @jsonable residual, host-ABI shape gaps),
ISSUE-0278 (JS lane failures), ISSUE-0380 (the nowMillis time lock),
ISSUE-0360 T14 (corpus destinations to be authored at the residual
absorption).
