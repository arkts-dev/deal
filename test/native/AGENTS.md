# Native fixtures

Committed strict-C11 fixtures for the published runtime suites. Every fixture compiles and links the published runtime tree produced by the deployment path, never a hand-assembled directory, with the pinned flag list at `-O0` and `-O2`. `module_stub.c` stands in for the emitted project module: it defines exactly the six export-surface functions and `deal_project_arm_table`, and a `-DDEAL_STUB_CASE`/`-DDEAL_FRAME_CASE`/`-DDEAL_QUEUE_CASE` variant is a distinct negative that must terminate with one deterministic stderr line and exit 2 rather than returning. `driver_main.c` and `export_probe.c` are driver-shape entry points; the product shape always links the published `main.c`. `registry_empty.c` is the count-zero generated registry sentinel. Every runtime suite also builds its committed driver and the published runtime with AddressSanitizer and UndefinedBehaviorSanitizer (`-fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer -g`, `NativeCompiler.SANITIZER_FLAGS`) at both levels and asserts the same exact observations with no finding, so an out-of-bounds access, a stale read of a reclaimed arena slot or an undefined operation is a report rather than a silent success. `queue_race_probe.c` and `gc_posters_probe.c` carry the further ThreadSanitizer variant (`-fsanitize=thread -g`). `gc_poison_probe.c` is the negative control of the collector's sanitizer poison: it refuses to compile without AddressSanitizer, and its stale read of a payload the collector reclaimed and poisoned must be the reported `use-after-poison` (the plain build of the same fixture must fail to compile). The race probe uses POSIX threads because the sanitizer does not intercept the internal pthread path glibc's `thrd_create` takes. Negative fixtures (`opacity_sizeof.c`, `opacity_allocate.c`, `module_stub_partial.c`) are expected to fail their build or link and are asserted as such. `value_storage_driver.c`, `memory_storage_driver.c`, `text_storage_driver.c` and `crossing_storage_driver.c` are the ISSUE-0905 acceptance drivers of the published value storage, layout/root/cell, text and crossing-value-table surface; each one's `-DDEAL_*_CASE` variants beyond case 0 are deterministic invariant faults that must terminate with one stderr line and exit 2 rather than returning. `boundary_driver.c` is the ISSUE-0907 acceptance driver of the descriptor atoms, the descriptor-driven check, class construction validation and the arm materialization: it prints one canonical tab-separated observation per boundary check, arm render and construction attempt, and the Java suite derives each expected line from the shared failure-projection authority (`BoundaryExecutor`, `FailureContractRegistry`) rather than from the observation itself; its `-DDEAL_BOUNDARY_CASE` variants beyond case 0 are the deterministic producer defects (malformed descriptor text, unknown/inner-only arm, parameter and field shape mismatches, an uninstalled table, duplicated and missing construction fields, a call-frame or boundary mismatch and a contradictory admission), each one stderr line and exit 2. `module_stub.c` cases 8-11 are the install entry's repertoire negatives — an unknown arm id, a missing arm, a parameter-shape mismatch and a declared-field mismatch — so the accepted table is the only shape that installs. `json_stdlib_driver.c` is the ISSUE-0908 acceptance driver of the published `json` and `std` service groups: it links the published tree, defines the six export-surface functions and the closed arm table as the emitted module, prints one canonical tab-separated observation per JSON round trip, numeric token, parse defect, encoding rule, stdlib operation and class-walk case, and stands in for the emitted per-class JSON plans with two test plans over a record-shaped instance (a driver-side stand-in for the emitted per-layout struct). Its `DEAL_JSON_CASE=<n>` environment value selects one deterministic producer or invariant defect instead of the acceptance run, so one product serves both. `json_stdlib_driver.c` also runs its whole acceptance matrix again under the process's ambient locale (`DEAL_JSON_LOCALE=1`, selected through `LC_ALL`) and refuses a locale whose decimal point is `.`: the numeric decode and encode entries run under one private C locale, so the observations must be byte-identical to the C-locale run. `gc_driver.c` is the ISSUE-0906 acceptance driver of the collector: it runs its whole matrix at `-O0` and `-O2` with and without `DEAL_GC_STRESS=1` and prints one identical line in every mode, because the switch changes collection timing only; its `-DDEAL_GC_CASE` variants beyond case 0 are the collector's deterministic invariant faults. It also pins the four properties the collector's physical behaviour rests on: a hundred thousand zero-payload allocations still reach the growth policy's trigger (which charges the allocation footprint, not the payload) and are all swept while the payload statistics stay zero; a wide object's resumable walk never spends more than `DEAL_GC_MARK_BUDGET_REFERENCES` reference visits per safepoint, visits every slot exactly once across the slices and therefore needs one safepoint per budget; a freed slot serves a smaller request and then a larger one inside the slot's original capacity, and a churn across every size class returns the arena pages so the resident set does not follow the churn volume; and a seeded mutation/deletion workload over a rooted reference graph keeps the collector's live object count equal to the model's reachable set with every reachable payload intact after each complete collection. Every managed value it keeps across another allocating call is rooted first, exactly as generated code roots its temporaries, so the stress plus poison run is a physical-safety observation rather than a use-after-free of the driver's own. Its barrier case is the one differential that cannot be uniform across the modes: a stress safepoint completes a cycle, so no marking phase is observable between two driver statements and the barrier's shade path is unreachable there, so that case asserts the exact survival/reclamation deltas in the non-stress run and the same live-result contract through the containers in a stress run, printing one identical line in both. Its allocation-mark case isolates the allocation-time mark in both modes: it fills the growth trigger exactly with dropped objects, starts the cycle with an explicit safepoint (whose atomic phase finds no root), and allocates the fresh node while the collector is already sweeping, writing it into a root slot only afterwards, so only that mark keeps it; both modes assert the same exact object, byte and swept-object deltas, which are one object and one payload lower and one swept object higher without the mark (under stress the object is rooted before every later collection, so the mark is only observable in the non-stress run). Its root-source case asserts that one complete cycle enumerates a registered source exactly twice (the cycle-start walk and the atomic-phase rescan) and that an idle period adds none, so deleting either enumeration fails it. `error_reclaim_driver.c` is the ISSUE-0906 platform-storage half of Error reclamation: it is linked with `-Wl,--wrap=malloc -Wl,--wrap=free` (and `-fno-builtin-malloc`/`-fno-builtin-free`, so neither level can inline the counted calls away), which redirects the runtime's only system-allocator calls — `deal_platform_allocate` and `deal_platform_release` in the published `platform.c` — to its counting wrappers; no published runtime symbol is replaced and the published tree stays byte-identical. It asserts the exact platform footprint of a live Error graph, that a fully live full collection releases none of it, that reclaiming the records returns the count exactly to its baseline (the copied text, the optional fields, the frames array and every duplicated label), and that record storage reused from the size-class free list receives fresh platform storage and is released in turn; it runs at both levels normally and under `DEAL_GC_STRESS=1` and prints one identical line in every mode. `gc_posters_probe.c` is the supplementary instrumented poster/collector probe: it refuses to compile without ThreadSanitizer and is compiled only by that supplementary case, never by a production build. Keep the fixtures small, independent and free of runtime implementations: a fixture never replaces a runtime symbol.
