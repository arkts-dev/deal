# Native fixtures

Committed strict-C11 fixtures for the published runtime suites. Every fixture compiles and links the published runtime tree produced by the deployment path, never a hand-assembled directory, with the pinned flag list at `-O0` and `-O2`. `module_stub.c` stands in for the emitted project module: it defines exactly the six export-surface functions and `deal_project_arm_table`, and a `-DDEAL_STUB_CASE`/`-DDEAL_FRAME_CASE`/`-DDEAL_QUEUE_CASE` variant is a distinct negative that must terminate with one deterministic stderr line and exit 2 rather than returning. `driver_main.c` and `export_probe.c` are driver-shape entry points; the product shape always links the published `main.c`. `registry_empty.c` is the count-zero generated registry sentinel. Two fixtures carry an instrumented variant, compiled only by its supplementary case and never by a production build: `queue_race_probe.c` under ThreadSanitizer (`-fsanitize=thread -g`) and `frames_driver.c` case 0 under UndefinedBehaviorSanitizer (`-fsanitize=undefined -fno-sanitize-recover=undefined`). The race probe refuses to compile without the sanitizer, and uses POSIX threads because the sanitizer does not intercept the internal pthread path glibc's `thrd_create` takes. Negative fixtures (`opacity_sizeof.c`, `opacity_allocate.c`, `module_stub_partial.c`) are expected to fail their build or link and are asserted as such. Keep the fixtures small, independent and free of runtime implementations: a fixture never replaces a runtime symbol.
